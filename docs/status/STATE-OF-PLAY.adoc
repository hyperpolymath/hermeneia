What is actually built, what is deliberately not, and what is known to be

For *why* the language exists see link:../THEORY.adoc[docs/THEORY.adoc]; for

This document is neither — it is the honest status board.

== One-line summary

A running vertical slice: one of seven voking operations works end to end
against the real checker, over a stub store. The theory is written; the
implementation is a beginning, not a product.

== What works, and what that proves

[source,text]
----
$ hermeneia query -e 'invoke "authentic language" \
    under use_model "critical-paraphrase" show verdict'

subject:   "authentic language"
use_model: "critical-paraphrase"
verdict:   p-insufficient
witness:   e_paraphrase (fate.quality)
           the `attenuate` step is where the floor was breached
----

Change one word and the verdict changes — on the *same particular*, the *same
path*, and the *same declared grade* of `Attenuated(6)`:

[cols="2,2,1,1",options="header"]
|===
| use-model | floor | verdict | exit

| `critical-paraphrase` | quality `Attenuated(3)` | p-insufficient | 1
| `loose-gloss`         | quality `Attenuated(10)`| p-sufficient   | 0
|===

The answer did not change; the *use* did. That is the
retrieved / interpretable / licensed trichotomy computing a verdict rather than
asserting one, and it is enforced on every push by the `Slice (end to end)`
workflow.

| `evoke`     | recognised, reports unimplemented | no | the refusal is tested | no
| `convoke`   | recognised, reports unimplemented | no | the refusal is tested | no
| `transvoke` | recognised, reports unimplemented | no | the refusal is tested | no
| `provoke`   | recognised, reports unimplemented | no | the refusal is tested | no
| `intervoke` | recognised, reports unimplemented | no | the refusal is tested | no
| `revoke`    | recognised, reports unimplemented | no | the refusal is tested | no

*Nothing is Integrated.* Vocarium does not exist; every result above is against
the in-repo JSONL stub and its seed corpus.

Output surfaces:

* `show verdict` — implemented, with witness edge and coordinate.
* `show loss` — *refused, not faked.* See <<known-broken>>.
* `show warrant`, `show failure_points` — refused; they need the warrant graph.

== Deliberate honesty properties

These are design decisions, not omissions, and each is covered by a test that
fails if it regresses:

* `evoke`…`revoke` parse and report *"recognised but not implemented"* — a
  distinct error from a syntax error.
* `JsonlStore::neighbours` returns `Unsupported`, never an empty vector, so an
  unimplemented `evoke` cannot masquerade as "no neighbours found".
* `Fate::from_json` rejects `Falsified`; the loader rejects deceptive grades.
  Under the `prevent` profile a deceptive grade cannot be emitted even by
  accident.
* The end-to-end suite *fails loudly without a checker* rather than skipping.
  It is gated behind `--features e2e`, and because a silent gate is the same
  sin, `tests/gate.rs` runs by default and goes red if the workflow stops
  opening it.

== Architecture in one rule

*Hermeneia does not implement the grade algebra.* It is proved in Idris2 inside
`trope-checker`; a second implementation here would fork the exact semantics the
design exists to protect. Hermeneia emits Trope IR v0.2 and delegates verdicts.

It is not a wrapper, though: only three of seven operations need a verdict at
all (`invoke`, `provoke`, `intervoke`). The rest are store traversal, path
composition, or licence state — which hermeneia owns.

== Instantiation — what `just init` now means here [[instantiation]]

This repository was scaffolded from
https://github.com/hyperpolymath/hermeneia[hermeneia] and never
rendered. Roughly 120 files shipped as an unrendered template: copyright headers
reading `2026 Jonathan D.A. Jewell (hyperpolymath)`, `CITATION.cff` with no title,
`ANCHOR.a2ml` with no `kind` or `domain`, the whole of `container/` addressed to
a service nobody named, and a `Justfile` declaring `project :=
"hermeneia"` — a repository asserting that it *was* the template, and
failing its own `methodology-guard` drift check for it.

*The root cause was not the tokens.* The root `Justfile` has imported
`build/just/init.just` since the scaffold, and that file never existed. `import?`
is an _optional_ import: just silently ignores a missing module. So the one
command that would have rendered the tree had no body, and no gate noticed the
body was missing. Filling tokens by hand once would have fixed the symptom and
lost the decisions — nothing to re-run, nothing to check, no way to tell a
rendered tree from a lucky one.

So the machinery came first, and was then used:

[cols="1,3"]
|===
| `.machine_readable/configs/instantiation.a2ml`
| The canonical values, each with its SOURCE named (README.adoc, EXPLAINME.adoc,
  the descriptiles, Cargo.toml, .github/SECURITY.md) — read out of this
  repository, not guessed. The four that need human judgement (`PROJECT_KIND`,
  `PROJECT_DOMAIN`, `PROJECT_UNIQUE_STRENGTH`, `LANG_STACK`) sit in a marked
  JUDGEMENT block quoting the document each came from, because upstream
  `repo-init` deliberately leaves those UNASSIGNED rather than write fiction into
  `ANCHOR.a2ml` — the file the estate treats as semantic authority.

| `scripts/instantiate.sh`
| The engine. Idempotent by construction: a rendered tree holds no tokens, so a
  second pass changes nothing (verified — two consecutive runs, zero files).
  Substitution is _literal_ (awk `index`/`substr`), not `sed` or a regex, because
  `{{` opens an interval quantifier in an ERE, `ugrep` on some estate machines
  rejects a bare doubled brace as an "empty (sub)expression", and `&` in a `sed`
  replacement means "the whole match". Derives what is derivable and never
  guesses: `PROJECT`/`project` from `REPO`, author name parts from `AUTHOR`, and
  `UUID` as UUIDv5(URL, `github.com/hyperpolymath/hermeneia`) — which reproduces
  the value `CLADE.a2ml` already carries, so the two cannot drift.

| `build/just/init.just`
| The missing import target. Deliberately *not* a copy of upstream's 963-line
  `repo-init.just`: that is a MINT recipe referencing `archetypes/`,
  `build/docs-seed/`, `build/templates/` and `scripts/rust-tool.sh`, none of
  which exist here, and every one of which would fail on first run. This is the
  narrow equivalent for a repository that already exists. Recipes: `just init`,
  `just init-check`, `just init-list`, `just placeholders`.

| `scripts/check-no-placeholders.sh`
| The estate's canonical gate, vendored VERBATIM from `hermeneia` so this
  repo and the template cannot drift on what "unfilled" means, plus one
  clearly-marked additive block for the template and example trees. Called from
  `openssf-compliance.yml`, from `scripts/validate-template.sh` Phase 5, and from
  the Mustfile's `no-placeholder-values` invariant — one implementation, three
  callers, which is the point.
|===

Two exclusions a blanket `sed` gets wrong, both flagged in issue #8:

* *Drift guards.* `methodology.a2ml`'s `reject-if-contains` and
  `methodology-guard.k9.ncl`'s `reject_patterns` list the literal token as a
  pattern to REJECT. Rendering them rewrites the guard into this repository's own
  name and silently disables the check. Those _lines_ are protected; the rest of
  both files renders normally.
* *Justfiles.* just owns brace interpolation there: the lowercase `project`,
  `args`, `tier` and uppercase `ARGS` tokens a recipe body carries are the
  variables the `Justfile` itself defines, not template placeholders. A blanket
  pass turns the recipe line that echoes the project variable into a literal and
  breaks every interpolating recipe. Justfile _identity_ is fixed at the variable
  definitions instead, which is where it was actually wrong.
+
That is not a hypothetical. An earlier pass of the renderer over this very
paragraph substituted the project token inside the sentence explaining why it must
not be substituted, and this bullet read "just owns brace interpolation there —
`hermeneia`". Tokens are named in words below for that reason.

Two tokens had *no possible value*, which the gate's own header says is worse
than absent, so the sections went rather than the gate staying red forever:
`.well-known/security.txt`'s `Encryption:` (no PGP key is published —
`.github/SECURITY.md` says one "can be arranged on request") and `Hiring:` (which
rendered to `https://https://github.com/...`, because the template prefixed a
value that is already an absolute URL, and there is no `/careers` page on a GitHub
repository); and `TEMPLATE-STANDARDS-AUDIT.adoc`'s OpenSSF Best Practices project
ID, which this project does not have. Both reasons are recorded in-file so nobody
"restores" them.

[NOTE]
====
Token names in this section are spelled out in *words*, not as brace tokens.
Writing one here would trip `scripts/check-no-placeholders.sh` — the gate this
section describes — because a real token is byte-identical to prose about a real
token unless the prose declines to spell it. Same hazard, same answer, as
`.machine_readable/self-validating/methodology-guard.k9.ncl` splitting its
reject-pattern across a Nickel concat so the renderer cannot match it, and as
upstream `repo-init` computing its brace delimiters with `printf` rather than
typing them. A gate that fires on its own explanation gets switched off.
====

== Verification — how to check these claims yourself

[source,bash]
----
# build the oracle (dependency-free, ~4s, no network needed)
cargo build --release --manifest-path ../trope-checker/src/rust/Cargo.toml
export HERMENEIA_TROPECHECK=$PWD/../trope-checker/src/rust/target/release/tropecheck-rs

cargo test --workspace                                    # 39 unit + gate tests
cargo test -p hermeneia-cli --features e2e --test slice   # 7 end-to-end tests
----

The end-to-end suite is validated against `trope-checker`'s conformance corpus —
the same oracle that validates its Rust fast core against the Idris2 reference.

== What comes next, in order

. *`evoke` / `convoke`* — store traversal, no checker. This forces the deferred
  decision: bounded traversal needs the retention order in-process. The door is
  now open — `tropecheck-rs` exposes a `[lib]` with `grade_le` as of
  trope-checker PR #46, so hermeneia can depend on the validated implementation
  instead of forking or shelling out.
. *`transvoke`* over Haec edges; then *`provoke`* and *`intervoke`*, which reuse
  the `invoke` path.
. *`revoke`* with a persisted warrant graph. Open design question: does licence
  state live here or in Vocarium?
. *Upstream:* have `tropecheck` emit the violated-coordinate list it already
  computes, so `show loss` can be honest.
. *`verification/proofs/idris2/Voke/`* — the voke-algebra laws. Not started, and
  deliberately *not* stubbed: this estate's proof gates are known to exit 0 when
  the prover is absent, so a stub would read as a passing milestone while
  proving nothing. Note `trope-checker` now declares its requirement as
  *Idris 2 0.8.0*.
